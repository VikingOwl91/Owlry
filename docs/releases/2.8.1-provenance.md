# Owlry 2.8.1 release provenance and publication plan

This document describes local release assembly. It does not authorize publication.
The proposed tag is `owlry-v2.8.1`, targeting the final reviewed assembly commit,
not the unrelated `docs/readme-refresh` checkout.

The AUR recipe deliberately downloads the immutable tested commit archive:
`https://somegit.dev/Owlibou/owlry/archive/387892ebb19e49604e74745a549ae0d0bfdaaf96.tar.gz`.
Migration scripts, hook, unit and packaged documentation are separate checksummed
local AUR sources. They become available from the committed `aur/owlry/` mirror
and must all be included in the subsequent AUR commit.

The assembled tag archive will differ from the frozen source archive because it
includes final packaging, documentation and a corrected install-message test.
It is not the archive used to build the frozen package. Rust source, Cargo
metadata and lockfile, original systemd units and all packaged executable inputs
are unchanged. Existing runtime and migration evidence therefore remains
applicable to the frozen package; it is not a claim that the assembled tag archive
has itself been rebuilt or integration-tested.

Keeping the immutable AUR source URL requires no checksum, URL or pkgrel change
after tagging. Changing that URL to the tag archive would create a different
build input and requires a separate provenance comparison and validation decision.

## File ownership

The source repository contains the canonical README and upgrade guide, changelog,
release notes, this record, the corrected non-packaged install-message test and
the `aur/owlry/` packaging mirror. No unrelated commits are integrated.

The AUR publication must contain exactly these release files, in addition to its
existing repository bookkeeping:

- `PKGBUILD`, `.SRCINFO`, `owlry.install`
- `owlry-user-migrate-run.sh`, `owlry-user-migrate.sh`
- `owlry-user-migrate.hook`, `owlry-user-migrate.service`
- `README.md`, `upgrading.md`

`aur/owlry/SHA256SUMS-migration` is a source-repository verification manifest;
its paths are relative to the source repository root. It is not an AUR build
input. Do not publish packages, source tarballs, build directories or nested Git
metadata as AUR source files.

Generated lab runs, payloads, cached dependencies and packages remain evidence
outside the release source tree. The full original lab is preserved; the local
assembly evidence bundle retains the frozen reports, referenced guest records,
package and source archive. It does not duplicate all dependency caches or VM
images. Historical source-exact 2.7.0 reconstruction is not authentication of
the originally published binary.

## Verification and limitations

The frozen records report T1–T10, M1–M10, 548 release-profile Rust tests,
formatting, Clippy and ShellCheck passes. Assembly checks compare source and
package inputs, validate metadata and run the corrected install-message test;
they do not rerun the full integration suite or rebuild the package.

Coverage is the pinned Arch guest with cached Arch/ALHP dependencies. There is no
official-only clean-chroot build, full Wayland GUI acceptance or independent
second VM execution. R12 and R13 remain lab resolver/parser defects; actual
frozen-payload transactions used dependency-enforcing pacman. The historical F3
root-side bus-symlink mechanism is removed; filesystem-availability impact remains
unverified. These were classified as nonblocking for the frozen package.

## Proposed publication sequence — requires explicit approval

1. Recheck the exact reviewed assembly commit/tree, package/input hashes and
   remote refs; stop if the tag already exists with a different target.
2. Push only the approved source commit/ref to the intended Owlry source remote.
   The configured source forge is `somegit.dev`; no GitHub mirror is assumed.
3. Create and push only `owlry-v2.8.1` at that exact assembly commit. Never tag
   current HEAD in another checkout, or push all local tags.
4. Publish the release notes from `docs/releases/2.8.1.md` on the explicitly
   approved forge. If publishing the frozen binary package, attach that exact
   artifact and its checksum; identify tag-generated source archives separately.
5. In a separate AUR checkout, commit only the nine listed release files,
   retaining their reviewed bytes. Compare `.SRCINFO` and every source checksum,
   inspect the outgoing diff, then push the exact approved AUR commit/ref.
6. Read back the source tag, release assets and AUR files and verify their identities.

Do not use `just release-owlry`, `aur-update`, `aur-stage` or `aur-publish` for
this release. Their existing automation assumes a tag-sourced archive and a
single-line checksum array, or omits the new auxiliary files. Use explicit
reviewed file/ref operations instead; fixing generic automation is outside scope.
